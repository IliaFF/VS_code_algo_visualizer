# Работа с Algo VS Code Extension

Агент изучает код и готовит объяснения; расширение отображает их и связывает с исходником. В нём нет самостоятельного анализатора, ИИ-запросов или верификатора. Результат работы — понятный анализ выбранного кода с проверенными привязками и явно указанными ограничениями, а не только успешно открывшаяся схема.

## 1. Выбери сценарий и границы

Установи корень расширения (`EXTENSION_ROOT`) и корень целевого проекта: это могут быть разные каталоги. От каталога этого скилла корень расширения — `../../../`. Прочитай правила целевого проекта; при работе над самим расширением — его [AGENTS.md](../../../AGENTS.md). Статусы задач расширения находятся в [TODO.md](../../../TODO.md), а не в скилле.

Уточни, что требуется: создать анализ, обновить существующий, открыть и изучить его или разобраться с ошибкой. Для подготовки данных определи выбранные алгоритмы и разрешённые изменения. Исходник сохраняй как предмет анализа: изменение кода ради схемы требует отдельной задачи.

Выбери ветку:

- **JSON-анализ любого целевого проекта** — основной режим. Для создания или обновления прочитай [подготовку анализа](AUTHORING.md); для открытия готового документа перейди к шагу 2.
- **Встроенный geometry без JSON** — прочитай [отдельную инструкцию](GEOMETRY.md). Его доверенные CJS-описания не являются внешним форматом.
- **Изменение реализации расширения** — используй [README](../../../README.md) для состава модулей, сборки и проверок; границы продукта заданы [спецификацией](../../../docs/specs/agent-analysis-interface.md). Этот скилл не заменяет согласование задачи разработки.

Перед переходом дальше должны быть известны сценарий, корень целевого workspace и файлы, которые разрешено менять. Установку зависимостей, установку/обновление расширения и действия в открытом пользовательском окне согласуй отдельно; сохраняй несохранённые данные.

## 2. Открой или обнови анализ

Для JSON используй **«Анализ агента: Открыть JSON рядом с кодом»** (`analysis.openDocument`) в VS Code с открытой папкой целевого проекта. Выбери документ; в multi-root сначала выбери корневую папку. Пути внутри JSON относительны выбранному корню workspace, не каталогу JSON. Поддерживаются файловые workspace (`file:`); в недоверенном workspace расширение не запускается. Доверие к проекту устанавливает пользователь.

Для примера без установки следуй [README](../../../README.md#посмотреть-новый-пример-без-установки): конфигурация F5 **«Анализ агента: открыть пример JSON»** в `geometry.code-workspace` открывает `examples/analysis-contract`. Запуск нового Development Host и любые действия с окнами выполняй только с разрешения пользователя. Изменение исходников расширения не обновляет установленную версию или уже работающий Host.

После сохранения изменённого JSON нажми **«Перезагрузить анализ»**. Автоматического наблюдения за JSON нет. Расширение не редактирует и не сохраняет ни JSON, ни исходник. При ошибке обновления остаётся последний корректный анализ с предупреждением: это не подтверждение загрузки новой версии.

Шаг завершён, когда открыт нужный документ относительно нужного корня и нет ошибки его загрузки. Если живой VS Code недоступен, передай пользователю эти действия, не объявляя открытие проверенным.

## 3. Используй связь объяснений с кодом

- Начни с обзора проекта, затем выбери раздел алгоритма. Обзор выборочный; отсутствие записи не доказывает отсутствие файла или связи. Независимые операции показываются списком, не последовательностью исполнения.
- Раскрой смысловой блок или нажми **«Все подробно»**, чтобы увидеть малые узлы и явные ветви. Краткое объяснение находится в карточке; **«Подробнее»** открывает подробности и свойства над графом.
- **«Показать участок кода»** ведёт от узла к исходнику, **«Показать код раздела»** — ко всему разделу. **«Код этого узла»** у крупного узла обзора показывает связанный раздел/файл; при нескольких файлах нужно выбрать участок. Наведение подсвечивает уже открытый редактор, а не открывает файл само.
- Поставь курсор или выдели текст в однозначном диапазоне: выбирается соответствующий малый узел и раскрывается его блок без перехвата фокуса редактора. Если пользователь зафиксировал детализацию кнопкой «Фиксировать детали», блок не раскрывается: меняется только подсветка узла. Пересекающиеся диапазоны, несколько курсоров и неоднозначные якоря не дают случайного выбора.
- Если для вспомогательной функции подготовлен раздел, открой её объяснение и вернись назад. Иначе доступен переход к её исходнику; собственной Call Hierarchy и вложенных графов нет.
- Масштаб кнопками −/+/100% или Ctrl+колесом меняет размер графа (25–200%), а не детализацию. Обычное колесо прокручивает; зажатая средняя кнопка перемещает область просмотра. Вокруг графа есть пустое поле размером с область просмотра с каждой стороны: точку обзора можно увести за край графа. Правый нижний угол рамки меняет её ширину и высоту, не масштаб и не размер редакторной панели. Выбранный размер рамки сохраняется до закрытия панели, включая переходы между графами и обзором, возврат со страниц без графа и перезагрузку анализа. Узлы вручную не перемещаются, автораскладки нет.

Шаг завершён, когда выбранный участок объяснён и сопоставлен с кодом либо явно указана причина недоступной связи. Утверждения о свойствах относятся к указанному участку, а не автоматически ко всей программе; результат верификатора из них не следует.

## 4. Разбери предупреждения, не маскируя их

| Симптом | Что проверить |
| --- | --- |
| JSON не открывается или не перезагружается | Поле и причину в сообщении; структуру и ссылки по [контракту JSON v1](../../../docs/specs/agent-analysis-format.md). При ошибке перезагрузки видимым может оставаться старый документ. |
| Недопустимый путь | Выбранный корень и относительный путь; доступ наружу, включая символьные ссылки, запрещён. Исправь данные или выбор корня, сохраняя проверку границ. |
| Исходник недоступен | Наличие файла в выбранном workspace. Объяснение остаётся доступным, но переход не подтверждён. |
| Якорь отсутствует или неоднозначен | Текущий текст, включая несохранённые изменения; точность и уникальность якорей в их области. Для исправления данных используй AUTHORING.md. |
| Хеш не совпал | Что изменилось в коде и зависимостях; обнови анализ по исходнику, а не только хеш. Предупреждение само по себе не отключает однозначные переходы. |
| Нет обратного выбора узла | Активный раздел, число выделений и попадание целиком в единственный диапазон узла. |
| После правки расширения поведение старое | Какой код загружен: установленная версия или Development Host. Отдельно согласуй новый запуск вместо автоматического обновления окна или установки. |

Не угадывай диапазон вместо ошибки. Совпавший хеш и сохранившийся якорь не доказывают актуальность объяснения или правильность алгоритма.

## 5. Проверь результат и передай его пользователю

Выбери проверки по изменённому результату:

- **Создан или обновлён анализ** — выполни структурные, текстовые и смысловые проверки из [AUTHORING.md](AUTHORING.md#проверка-подготовленного-документа). Сам разбор исходника не заменяется валидатором.
- **Открыт существующий анализ** — проверь загрузку нужной версии и переходы для изучаемых участков; сообщи предупреждения и границы покрытия.
- **Изменён код расширения** — запусти проверки из README, `node --check` изменённых JS/CJS и сверь явный состав пакета в `package.mjs`. Тесты с подменой VS Code API и браузер со stub-мостом не подтверждают живой Extension Development Host.

Живую проверку после изменения данных или интерфейса согласуй с пользователем: обзор → раздел → блок → малый узел; код ↔ узел и сохранение фокуса; крупный узел и выбор файла; вспомогательная функция и возврат; все явные ветви после раскрытия; свойства нужной области; масштаб, панорамирование и resize; узкая/широкая панель и Tab; несохранённая правка и неоднозначный якорь; успешная/ошибочная перезагрузка и закрытие панели. Пробные правки исходника не сохраняй без разрешения.

В ответе укажи путь JSON и корень для его открытия, границы анализа, выполненные проверки и оставшиеся предупреждения или действия пользователя. Для просмотра без создания JSON укажи изученные разделы. Завершение означает выполнение согласованных проверок; недоступная живая проверка остаётся непроверенной. Если тесты доступны агенту для изменения, это самопроверка, не независимый контроль.
