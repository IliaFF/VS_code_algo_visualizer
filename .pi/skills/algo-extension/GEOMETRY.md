# Встроенный geometry без JSON

Эта ветка [algo-extension](SKILL.md) относится только к старому встроенному примеру. Для другого проекта готовь JSON по [AUTHORING.md](AUTHORING.md), а не внешние исполняемые описания.

## Открытие и просмотр

Команда **«Geometry: Открыть схему рядом с кодом»** (`geometry.openDiagram`) открывает встроенное описание. В `geometry.code-workspace` есть отдельная F5-конфигурация **«Geometry: открыть проект со схемами»** для `examples/geometry`. В установленной версии нужна папка с тем же расположением `raytracing/geometry`. Открытие окон и запуск согласуй с пользователем, как в основном скилле.

Классы показываются списком независимых операций; отдельные этапы и вызовы удалены. В режиме разработки доступен флажок **«Geometry: демонстрационные статусы свойств»**: он показывает оформление, не запускает верификатор. После правок кода демостатусы устаревают; в Production переключатель скрыт.

## Если согласована правка встроенного описания

Доверенные описания находятся в `diagrams.cjs`, привязки — в `bindings.cjs`. Это укрупнённые блоки с якорями и диапазонами до следующего блока; конец функции ищется по отдельной строке `}`. Такая эвристика не поддерживает произвольный C++ и не доказывает полноту графа.

Сохраняй уникальность и порядок якорей, проверяй реальные диапазоны через `resolveView` и существующие тесты. Исходники C++ сохраняй неизменными ради схемы; файлы примера меняй только по отдельному запросу. Снимок `examples/geometry` не синхронизируется с внешним учебным репозиторием.

Укрупнённое описание называй полным графом лишь после сверки всех явных путей с исходником, а не по успешной привязке. Почти вырожденная геометрия, допуски и арифметика double требуют отдельного численного анализа. Завершение работы означает проверку согласованных описаний и диапазонов; живое отображение и математическая корректность не следуют из тестов якорей. Статус проектных доработок смотри в корневом TODO.md.
