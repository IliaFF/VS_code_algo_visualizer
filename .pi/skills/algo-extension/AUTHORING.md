# Подготовка и обновление JSON-анализа

Эта ветка [algo-extension](SKILL.md) нужна при создании данных или исправлении объяснений и привязок. Для просмотра готового документа достаточно основного скилла.

## Источники формата

Перед записью JSON прочитай [контракт версии 1](../../../docs/specs/agent-analysis-format.md) и [спецификацию результата](../../../docs/specs/agent-analysis-interface.md). Термины определены в [GLOSSARY.md](../../../GLOSSARY.md). Рабочий пример — [analysis.json](../../../examples/analysis-contract/analysis.json) рядом с [algorithm.cjs](../../../examples/analysis-contract/algorithm.cjs). Контракт — источник полей, допустимых значений и ограничений; пример не заменяет его.

Загрузчик принимает декларативный JSON v1. Объяснения — обычный текст, не HTML. CJS/JS из чужого проекта не выполняются как описания. Новые документы не содержат демостатусов, доказательств или отчётов верификатора.

## Порядок анализа

1. **Определи покрытие.** Обзор проекта может быть выборочным, но выбранную функцию разбирай целиком. Фрагмент обозначай `scope: "fragment"` с границами, а не полным графом функции. Результат шага — явно названная область анализа.
2. **Прочитай код и зависимости.** Изучи исходник, объявления и вызываемый код. Сверь рабочие файлы со снимками: одноимённые файлы не обязательно одной версии. Для вспомогательной функции без отдельного описания сохрани объяснение роли вызова и переход к исходнику. До разбиения должны быть понятны все явные переходы выбранной области.
3. **Разбей на малые смысловые участки.** Дай каждому действию или решению название, краткое объяснение «что и зачем», при необходимости `detail`, и точный диапазон. Сложная функция не скрывается под одним общим названием; узлы не создаются механически на каждую строку. Каждый узел должен объяснять свой участок кода.
4. **Запиши все явные пути.** Учти условия, варианты `switch`, циклы, `break`, `continue`, ранние выходы и написанную обработку исключений. Раздели `&&`/`||` согласно короткому замыканию; `continue` в `for` ведёт через приращение. Перехватываемый внутри области `throw` ведёт к обработчику, а не к конечному выходу. Каждое ребро имеет основание в исходнике, не в соседстве узлов в JSON. Недостижимый код объясни без выдуманного исполнимого ребра. Внутренности библиотек и неявные действия среды оставь за границей с явной оговоркой. Завершение шага — учтён каждый явный путь, включая ошибки, либо обозначена граница фрагмента.
5. **Подготовь уровни представления.** Для алгоритма используй `graph` с `entry`, строками/столбцами и явными рёбрами. Для независимых операций — `layout: "list"` без рёбер. Подготовь раскрываемые смысловые блоки с `id`, `summary`, `range` и дочерними узлами по контракту; диапазон содержит код всех детей, объяснение учитывает ранние выходы. Это уровни одного графа, не отдельная вкладка этапов. Описание вспомогательной функции открывается через `callee.section` с возвратом, не вложенным графом. При полном раскрытии сохраняются все исходные узлы и переходы.
6. **Добавь обзор и свойства.** Обзор объясняет роли выбранных каталогов/файлов и до 20 смысловых узлов с подписанными связями. Лимит 20 не относится к графу алгоритма. Положение не доказывает порядок исполнения; отсутствие записи не доказывает отсутствие файла или связи. Свойства добавляй по правилам ниже, только при содержательном основании.
7. **Подготовь привязки и проверь документ.** Выполни проверки ниже для каждого описанного файла, раздела, узла и раскрываемого блока. Затем снова сверь каждую ветвь с исходником. Готовность данных означает прохождение технических проверок и смысловую сверку, а не доказанную корректность алгоритма.

## Привязки и актуальность

Пути относительны выбранному корню workspace, без выхода наружу, в том числе через ссылки. Файлы из `callee` также должны быть описаны в документе.

Якоря `range.start/end` — точный текст, включая отступы. Якорь раздела ищется во всём файле, узла и блока — внутри раздела, `callee` — в его файле; каждый должен быть уникальным в своей области. Контекст якоря входит в связанный диапазон. Пересекающиеся диапазоны допустимы, но при неоднозначности обратный выбор намеренно не угадывает узел. Для уникальности меняй текст якоря в данных, не исходный алгоритм.

Хеш вычисляй через экспорт `digest(text)` из `analysis.cjs`: один начальный BOM удаляется, CRLF/CR приводятся к LF, прочие символы не меняются. Побайтовый `sha256sum` не заменяет этот алгоритм для исходника с CRLF/BOM. Для каждого описанного исходного файла запиши `sha256`. При открытом несохранённом документе расширение сравнивает данные с текущим текстом буфера, а не только с диском.

При изменении кода обновляй объяснения, переходы, якоря и хеши согласованно. Сохранившийся якорь не означает актуальное объяснение; совпавший хеш не доказывает правильность алгоритма или межфайловых связей. Несовпадение хеша даёт предупреждение, не скрывая описание.

## Свойства

Предусловия, постусловия, инварианты и контракты данных добавляй при основании в коде или требованиях. Укажи `subject`, раздел и при необходимости узел: например, конкретную голову цикла или структуру данных. Инвариант цикла относится к циклу, а обязанность вызывающего кода не становится проверкой контейнера.

Если содержательного свойства нет, оставь его отсутствующим; пустые поля не показываются. Утверждение агента и результат верификатора — разные вещи.

## Проверка подготовленного документа

Используй настоящий модуль расширения. `EXTENSION_ROOT` и `ANALYSIS_JSON` ниже — абсолютные пути:

```bash
node -e 'const fs = require("node:fs"); const {parseAnalysis} = require(process.argv[1]); parseAnalysis(fs.readFileSync(process.argv[2])); console.log("JSON OK");' "$EXTENSION_ROOT/analysis.cjs" "$ANALYSIS_JSON"
```

Команда проверяет структуру и ссылки документа, но не смысл графа или фактические диапазоны.

Для каждого файла сверь `digest(text)` и вызови `resolveSection(text, section)`; проверь `binding` раздела и узлов и отсутствие `bindingError`. У раскрываемых блоков проверь `groups[].binding`, затем сравни исходные узлы/рёбра с результатом полного раскрытия. API работает с текстом, не выполняя исходник. Пример вызовов и проверок — [test/analysis.test.cjs](../../../test/analysis.test.cjs). Масштаб меняет только размер графа и не заменяет смысловое разбиение.

Сверь каждый переход, объяснение и область свойства с исходником; отдельно перечисли ограничения полноты. Техническая проверка не делает эту сверку автоматической. Фактический корень, допустимость ссылок и работу с текущим буфером проверь загрузкой в панели по [основному скиллу](SKILL.md#2-открой-или-обнови-анализ), сохраняя проверки допустимости пути. Если живой редактор недоступен, этот этап остаётся пользователю.
