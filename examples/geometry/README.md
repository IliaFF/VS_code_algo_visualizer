# Geometry — локальный пример

`raytracing/geometry/include` и `raytracing/geometry/src` содержат неизменённый снимок 14 C++-файлов geometry на момент переноса расширения в самостоятельный проект.

Это данные для анализа и проверки привязок, не отдельная C++-сборка. Расширение читает исходники как текст; сборочная инфраструктура и штатные C++-тесты учебного репозитория сюда не переносятся.

## Новый анализ JSON

`analysis.json` подготовлен с нуля по исходнику: обзор всех файлов, графы всех определённых функций, списки независимых операций, объяснения и содержательные свойства. Это анализ снимка, не всего raytracer; неявные действия среды и внутренности библиотек не разворачиваются. Численная устойчивость и корректность C++ не доказаны.

1. Откройте эту папку (`examples/geometry`) как корень workspace с доступным расширением.
2. Выполните **«Анализ агента: Открыть JSON рядом с кодом»** и выберите `analysis.json` из этой папки.
3. В обзоре выберите модуль, затем операцию списка и её отдельное объяснение. Для алгоритма раскройте смысловые блоки или нажмите **«Все подробно»**.
4. Проверьте переходы к коду и обратный выбор. У повторяющихся `return std::nullopt` якорь включает контекст условия: при пересечении диапазонов обратный выбор намеренно не угадывает узел; этот предел указан в подробностях соответствующих узлов.

Из корня расширения F5-конфигурация **«Geometry: открыть проект со схемами»** открывает эту же папку в Development Host. В ней можно выбрать новую команду JSON вместо старой команды Geometry. Существующий пользовательский редактор перезапускать не требуется.

После изменения JSON используйте **«Перезагрузить анализ»**. Несохранённый текст исходника учитывается; пробные вставки и изменения якорей можно отменить через Undo без сохранения.

## Старый режим

Команда **«Geometry: Открыть схему рядом с кодом»** по-прежнему использует укрупнённые описания из корневого `diagrams.cjs`, а не этот JSON. Эти описания не заменены и не выдаются за новый полный анализ.
