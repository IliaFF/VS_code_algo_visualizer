# Algo VS Code Extension

Репозиторий: https://github.com/IliaFF/VS_code_algo_visualizer

Расширение — интерфейс для результатов анализа агента. Агент изучает целевой проект и готовит JSON; расширение показывает объяснённый граф алгоритма и связывает его с настоящим исходником в редакторе. Самостоятельного анализатора, встроенных ИИ-запросов и верификатора нет.

Сторонних JavaScript-зависимостей нет, `npm install` не нужен. Установленное расширение автоматически не обновляется при изменении этих исходников.

## Установить готовое расширение

Скачайте `geometry-diagrams-<версия>.vsix` из [GitHub Releases](https://github.com/IliaFF/VS_code_algo_visualizer/releases/latest) и выберите в VS Code Extensions → … → **Install from VSIX…**. Нужен VS Code 1.85+; Node.js, npm и компилятор C++ для установки не требуются. Идентификатор `local-geometry.geometry-diagrams` сохранён, обновление из Marketplace не настроено.

[Полная инструкция установки и первого запуска](docs/INSTALL.md) включена в VSIX как его README. Для готового JSON geometry скачайте исходники того же релиза, откройте `examples/geometry` и выберите `analysis.json` существующей командой **«Анализ агента: Открыть JSON рядом с кодом»**. Генерация анализа выполняется внешним агентом, не самим расширением.

## Посмотреть новый пример без установки

1. Откройте `geometry.code-workspace` в VS Code. Для WSL из корня проекта: `code --new-window geometry.code-workspace`.
2. В Run and Debug выберите **«Анализ агента: открыть пример JSON»** и нажмите F5. Новое окно Extension Development Host откроет `examples/analysis-contract` с текущим кодом расширения.
3. В новом окне выполните **«Анализ агента: Открыть JSON рядом с кодом»** через Ctrl+Shift+P и выберите `analysis.json`.
4. В обзоре выберите «Накопление». Нажмите на узел, чтобы прочитать подробности и свойства, затем **«Показать участок кода»**.
5. Поставьте курсор или выделите текст внутри связанного участка исходника: соответствующий узел выбирается без перехвата фокуса. Для вспомогательной функции доступно отдельное объяснение и возврат назад.

Не нужно закрывать или перезагружать уже открытое пользовательское окно. Если старый Development Host был запущен до изменений, он мог сохранить прежние модули: проверяйте новый запуск сами, не считайте старую панель обновлённой автоматически.

## Целевой проект и данные агента

Откройте папку целевого проекта и выполните ту же команду загрузки JSON. В multi-root сначала выберите корневую папку. Пути в документе относительны ей, а не каталогу JSON. Сейчас поддерживаются файловые workspace (`file:`), не произвольные виртуальные провайдеры. Доступ за пределы корня, в том числе через символьные ссылки, запрещён.

- [Спецификация результата](docs/specs/agent-analysis-interface.md).
- [Контракт JSON версии 1](docs/specs/agent-analysis-format.md).
- [Исходник примера](examples/analysis-contract/algorithm.cjs) и [его описание](examples/analysis-contract/analysis.json).

Структура и ссылки JSON проверяются до использования. Объяснения отображаются как текст, не исполняемая разметка. Данные CJS/JS из проекта не загружаются как описания.

### Что показывает панель

- Общую логику и выборочное распределение функций по каталогам и файлам; отсутствие записи не доказывает отсутствие файла или связи.
- Визуальный обзор до 20 смысловых частей с подписанными связями. В обзоре и графе алгоритма наведение на стрелку или её подпись выделяет всю связь и оба блока; то же выделение доступно при переходе к стрелке клавишей Tab. Это не меняет выбранный узел и не переводит редактор к другому коду. Длинные подписи переносятся и размещаются без наложения на карточки и друг на друга.
- Граф алгоритма с явными рёбрами: условия, циклы, выходы. Агент задаёт строки/столбцы узлов; порядок в массиве сам по себе не создаёт перехода. Лимит 20 узлов не относится к графу алгоритма.
- Промежуточную детализацию: смысловые блоки раскрываются до малых узлов в том же графе. Выберите блок → «Раскрыть», либо нажмите «Все подробно». Кнопка «Фиксировать детали» рядом с −/+/100% оставляет текущий набор раскрытых блоков неизменным: при движении по коду узел подсвечивается, но блок не раскрывается. Если код относится к другому разделу, он открывается свёрнутым, а подсвечивается блок с выбранным узлом. В свёрнутой карточке отмечены скрытые условия и выходы; полный граф и его рёбра сохраняются.
- Малые смысловые участки: краткое объяснение в карточке; «Подробнее» открывает объяснение, свойства и переходы к коду отдельным закрываемым блоком над графом, без боковой колонки. Выбор малого участка в редакторе раскрывает нужный блок.
- Независимые операции — списком, без выдуманной последовательности.
- Содержательные предусловия, постусловия, инварианты и контракты данных с областью действия. Пустые свойства скрыты; утверждения агента не являются результатами доказательства.
- Вызов можно объяснить в узле и открыть описание вспомогательной функции. Собственной Call Hierarchy нет; техническая иерархия зависит от встроенной поддержки языка в VS Code.

Полный разбор функции — требование к агенту, не автоматически проверенная гарантия интерфейса. Фрагменты явно помечены. Неявные действия среды и внутренности библиотек не разворачиваются. Граф можно прокручивать и масштабировать кнопками −/+/100% или Ctrl+колесом (25–200%). Масштаб сохраняется при выборе узла, обычное колесо прокручивает; уровень детализации меняется отдельно. Зажмите среднюю кнопку мыши для перемещения области просмотра: вокруг графа есть пустое поле размером с рамку, поэтому точку обзора можно увести за любой его край и обычное колесо прокручивает это поле тоже. Потяните за правый нижний угол рамки графа, чтобы изменить её ширину и высоту, не меняя масштаб или размер панели VS Code. Ширина ограничена панелью, высота — 80% окна; большой граф прокручивается внутри рамки. Выбранный размер рамки сохраняется до закрытия панели: при выборе узлов, раскрытии блоков, переходах между графами и обзором, возврате со страниц без графа и перезагрузке анализа. Уже видимый узел только подсвечивается: положение графа не меняется. Для скрытого за краем узла выполняется минимальная плавная прокрутка без центрирования и изменения масштаба. Раскрытие и сворачивание анимированы; системная настройка уменьшения движения отключает анимацию. Автораскладки и перемещения самих узлов нет.

### Привязки, актуальность и обновление

У крупных узлов обзора есть кнопка «Код этого узла»: она показывает весь связанный раздел/файл. Для нескольких описанных файлов появляется список участков для выбора. Наведение подсвечивает однозначный участок уже открытого редактора, не открывая его само. Смысловой блок имеет собственный диапазон, содержащий код всех его малых узлов; кнопка «Показать код раздела» показывает раздел целиком.

Точные уникальные текстовые якоря связывают узлы с исходником без парсера языка. Несохранённый текст учитывается; отсутствующий или неоднозначный якорь отключает соответствующий переход, не уничтожая объяснение. Выделение нескольких узлов и несколько курсоров не выбирают узел наугад.

SHA-256 канонического текста позволяет заметить изменение исходника. BOM и тип перевода строк не влияют на хеш; остальные изменения — влияют. Предупреждение не скрывает объяснение и не доказывает, что оно неверно. Совпадение хеша не подтверждает качество анализа и актуальность других файлов.

После сохранения обновлённого JSON нажмите **«Перезагрузить анализ»**. Автоматического наблюдения за JSON нет. Ошибка новой версии сохраняет последний корректный обзор с явным сообщением. Недоступный исходник отключает привязку, но оставляет описание. Устаревшие сообщения и отложенные действия не должны заменять новые привязки.

Расширение не редактирует и не сохраняет исходники или JSON, не выполняет команды из описаний и не обращается к сети. В недоверенном workspace оно не запускается. Закрытие панели удаляет подсветку и обработчики.

## Скилл агента

[`.pi/skills/algo-extension/SKILL.md`](.pi/skills/algo-extension/SKILL.md) описывает работу агента с расширением: подготовку и обновление анализа, открытие JSON, навигацию код ↔ граф, разбор предупреждений и проверки. Подготовка полных графов, якорей, хешей и свойств и работа со встроенным geometry вынесены в справки рядом со скиллом.

В Pi для этого репозитория после `/reload` доступен `/skill:algo-extension` (прежнее имя — `geometry-diagram-author`). В другом проекте передайте агенту путь к этой инструкции явно: расширение не устанавливает скилл в чужой workspace автоматически. Скилл не запускает агента из расширения: это инструкция агенту, который готовит данные.

## Новый JSON-анализ geometry

[`examples/geometry/analysis.json`](examples/geometry/analysis.json) — новый анализ всех 14 C++-файлов снимка, подготовленный с нуля: 54 графа функций, списки независимых операций и обзор модулей. Для открытия выберите `examples/geometry` как корень workspace, выполните **«Анализ агента: Открыть JSON рядом с кодом»** и выберите этот JSON. Подробности и ограничения — в [README примера](examples/geometry/README.md).

Это отдельные данные нового режима: прежние описания в `diagrams.cjs` не заменяются. C++ остаётся неизменным; анализ не является доказательством корректности или численной устойчивости.

## Старый встроенный geometry

В F5-конфигурации **«Geometry: открыть проект со схемами»** откроется `examples/geometry`. Выполните **«Geometry: Открыть схему рядом с кодом»**. В установленной версии можно открыть любую папку с этим же расположением `raytracing/geometry`.

Сохраняется прежний подход к расположению блоков и выбору исходника. Классы показывают независимые операции списком; отдельные вкладки этапов и вызовов удалены. В Development Host доступен флажок **«Geometry: демонстрационные статусы свойств»**. Он только показывает оформление, не запускает проверку; после правок демостатусы устаревают. В установленном Production-режиме переключатель скрыт.

Это укрупнённые описания, ещё не доработанные до новых требований полного графа. Привязки geometry используют старую эвристику конца функции по отдельной строке `}`; она не является анализатором C++. Снимок `examples/geometry` не синхронизируется со старым учебным репозиторием. Почти вырожденная геометрия, допуски и арифметика double требуют отдельного численного анализа; прохождение якорей ничего об этом не доказывает.

## Структура и проверки

- `analysis.cjs` — контракт, хеширование и точные диапазоны нового формата.
- `analysis-session.cjs` — загрузка, корень файлов, документы, перезагрузка, протокол панели.
- `analysis-webview.js` — граф, списки, объяснения и свойства.
- `extension.cjs` — команды и сохранённая сессия geometry.
- `diagrams.cjs`, `bindings.cjs` — старые описания и привязки geometry.
- `webview.cjs`, `webview.js`, `webview.css` — шаблоны, старый интерфейс и общие стили.
- `docs/specs/` — согласованные границы и формат; `GLOSSARY.md` — термины.
- `test/` — логика, filesystem-границы и протокол с подменой VS Code API.
- `TODO.md` — статус задачи и оставшаяся приёмка.

Нужен Node.js 18 или новее:

```bash
npm test
```

Отдельная браузерная регрессия масштаба (нужен установленный `google-chrome`, либо путь к нему в `CHROME`; ничего не устанавливает):

```bash
node test/browser-scale.cjs
node test/browser-viewport.cjs
```

Проверяет 25–200%, включая 60% и 75%, кнопки и Ctrl+колесо, дополнительный масштаб родительского слоя, привязку обоих концов стрелок и неизменность маршрутов при масштабировании. На настоящих данных обзора geometry проверяет отсутствие перекрытий подписей и карточек, полноту текста, наведение и клавиатурный фокус стрелок, выделение точных концов связи и сохранение выбранного узла без сообщений редактору. Карточки и SVG масштабируются единым слоем, без перераскладки и пересоздания стрелок; размеры области прокрутки меняются вместе с ним. Отдельный `browser-viewport.cjs` проверяет сохранение ручного размера рамки при выборе узлов, раскрытии блоков, навигации и перезагрузке анализа в узкой и широкой панели.

Структурная проверка собственного JSON из корня расширения:

```bash
node -e 'const fs = require("node:fs"); require("./analysis.cjs").parseAnalysis(fs.readFileSync(process.argv[1])); console.log("JSON OK");' /path/to/analysis.json
```

Она не проверяет смысл графа, фактические файлы и читаемость. Автотесты с подменой API и браузерный рендер с подменой моста не заменяют живой VS Code.

Ручная приёмка: проверить обзор и все явные переходы по исходнику; узел → код и код → узел; вспомогательную функцию и возврат; свойства нужного участка; узкую/широкую панель, Tab и тему; несохранённую вставку; неоднозначный якорь; корректную и ошибочную перезагрузку; закрытие панели. Не нужно сохранять пробные правки исходника. Оставшиеся проверки перечислены в `TODO.md`; прежние Blocked-задачи автоматически не закрываются.

## Сборка и установка

Нужны Node.js и системный `zip`:

```bash
npm run test:package
npm run package
```

Результат — `dist/geometry-diagrams-0.2.0.vsix`. Для сборки и отдельной проверки пакета нужны Node.js, системные `zip` и `unzip` (например, в Linux/WSL); npm-зависимостей нет. Существующий файл не перезаписывается; другой путь можно передать как `node package.mjs /путь/к/файлу.vsix`. Сборка ничего не устанавливает и не загружает из сети.

В VSIX входят только исполняемые файлы, manifest и инструкция установки; примеры, тесты, скиллы и локальные настройки не включаются. Проверка пакета сверяет полный состав, байты, метаданные, ссылки инструкции, импорты и синтаксис runtime, работу из другого каталога и отказ перезаписи. Она не устанавливает пакет и не доказывает работу живого редактора.

Установка/обновление — отдельное действие пользователя через Extensions → … → Install from VSIX. Издатель `local-geometry` локальный, пакет не подписан и не опубликован в Marketplace. Исходники и тесты сами по себе не обновляют ранее установленную WSL-версию 0.1.0.
