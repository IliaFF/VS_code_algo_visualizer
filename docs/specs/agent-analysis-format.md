# Контракт документа анализа, версия 1

Версия 1 реализована в `analysis.cjs`, загрузка и протокол панели — в `analysis-session.cjs`. Запуск описан в [README](../../README.md). Тесты с подменой редактора не являются живой приёмкой VS Code.
Границы продукта и приёмка: [спецификация](agent-analysis-interface.md).
Пример: [analysis.json](../../examples/analysis-contract/analysis.json), исходник: [algorithm.cjs](../../examples/analysis-contract/algorithm.cjs).

Документ — результат анализа агента, не программа, отчёт верификатора или автоматически доказанный полный граф. Расширение проверяет структуру и привязки, а агент отвечает за объяснения и сверку всех явных путей управления с исходником.

## Общие правила

- UTF-8 JSON-объект; поля и значения чувствительны к регистру. Версия задаётся целым числом `1`.
- Все перечисленные ниже поля обязательны, кроме явно отмеченных `?`. Неизвестные поля и версии отклоняются, чтобы не терять данные молча. Автор не повторяет ключи JSON-объекта.
- `id` — непустая строка по шаблону `[A-Za-z][A-Za-z0-9_-]*`. Идентификаторы разделов уникальны в документе, идентификаторы узлов — внутри своего графа или списка. Все ссылки разрешаются до показа документа.
- Названия, краткие и подробные объяснения — обычный текст, не HTML/Markdown. Названия и краткие объяснения непусты после удаления крайних пробелов. `detail?` и `properties?` можно опустить; `null` не заменяет отсутствие поля.
- Порядок элементов списков сохраняется. Рёбра существуют только при явной записи, соседство в массиве их не создаёт.

## Корневой объект

| Поле | Тип и назначение |
| --- | --- |
| `version` | `1` |
| `title` | Название анализа |
| `summary` | Общая логика и границы выборочного покрытия |
| `entries` | Непустой массив описанных каталогов и файлов |
| `overview` | Граф смысловых частей проекта, не Call Hierarchy |
| `sections` | Непустой массив описаний алгоритмов или независимых операций |
| `properties?` | Массив содержательных свойств; отсутствие или пустой массив скрывает секцию |

Интерфейс всегда обозначает покрытие проекта как выборочное. `summary` уточняет конкретные границы. Полнота выбранной функции и полнота покрытия проекта — разные требования.

## Каталоги, файлы и пути

Элемент `entries`:

- `path`: уникальный путь относительно выбранной папки workspace;
- `kind`: `directory` или `file`;
- `summary`: назначение;
- `sha256`: обязателен только для `file`, запрещён для `directory`. Это 64 шестнадцатеричных символа нижнего регистра, хеш текста при анализе.

Пути используют `/`, без завершающего `/`, пустых сегментов, сегментов `.` или `..`, обратной косой черты, `:`, управляющих символов и абсолютных адресов. Исключение: `.` обозначает корневой каталог только в записи `directory`. Пути не URL и не декодируются как URL. В корень нельзя выйти и через символьную ссылку. Каталог не раскрывается автоматически: интерфейс показывает описанные агентом записи.

Каждый файл, упоминаемый разделом или ссылкой на исходник, должен иметь запись `file`. Отсутствующий файл не делает объяснение недоступным, но переход отключается с ошибкой и актуальность не подтверждается. Недопустимый путь отклоняет весь документ до открытия файлов.

### Хеш и текст

Перед хешированием и поиском якорей один и тот же текст приводится к канонической форме:

1. Декодировать UTF-8 без молчаливой замены повреждённых байтов; для открытого документа взять текущий текст буфера.
2. Удалить один начальный U+FEFF, если он есть.
3. Заменить CRLF и одиночный CR на LF.
4. Не обрезать пробелы и конечные переводы строк, не нормализовать Unicode.
5. Для SHA-256 закодировать полученный текст в UTF-8.

Хеш относится к тексту, не к исходным байтам файла. Переключение LF/CRLF или BOM не меняет его; прочие текстовые изменения меняют. Совпадение хеша не подтверждает правильность объяснения или актуальность других файлов. Несовпадение оставляет объяснение видимым с предупреждением и не отключает однозначные якоря само по себе. Во всех упомянутых открытых файлах учитывается несохранённый текст.

## Текстовый диапазон `range`

```json
{"start": "точный начальный фрагмент", "end": "точный конечный фрагмент"}
```

Оба якоря — непустые строки в канонической форме LF. Поиск буквальный, без регулярных выражений, обрезания отступов или догадок о синтаксисе языка.

В указанной области каждый якорь должен встречаться ровно один раз, с учётом перекрывающихся вхождений. Начало диапазона — начало `start`, конец — позиция сразу после `end`; концы не включаются в смысле VS Code Range. Конечный якорь не начинается раньше начального, конечная позиция не раньше конца начального якоря. Одинаковые якоря обозначают один точный фрагмент. Вхождения ищутся независимо во всей области, не «первое подходящее после start».

- Диапазон раздела ищется во всём файле.
- Диапазон узла ищется только внутри успешно разрешённого диапазона раздела.
- Диапазон ссылки `callee` ищется во всём её файле.
- Диапазон раскрываемого смыслового блока ищется внутри раздела; он должен содержать привязки его малых узлов.

Можно использовать многострочный якорь для уникальности. Его текст целиком входит в диапазон; расширение не умеет отделять контекст поиска от выбранного участка. Позиции рассчитываются в UTF-16, как в VS Code; номер строки не часть формата. При переводе в координаты редактора учитывается исходное представление текста, включая BOM и окончания строк.

Неразрешимый диапазон раздела отключает привязки его узлов, а не объяснение и не весь обзор. Ошибка узла отключает только его привязку. Ошибка `callee` отключает только переход к вызванному коду.

Код → узел: выбор должен целиком находиться ровно в одном разрешённом диапазоне узла текущего раздела. Несколько подходящих узлов, несколько выделений или пересечение границ не выбирают узел наугад. При переходе в другой раздел он выбирается только при единственном подходящем разделе; иначе текущий раздел остаётся, выбор узла снимается. Пустой курсор на общей границе относится к диапазону справа, не одновременно к двум диапазонам. Обратный выбор сам по себе не перехватывает фокус. Блок → код использует весь диапазон узла.

## Обзор проекта

`overview` содержит `nodes` и `edges`.

Узел: `{id, title, summary, row, column, target}`. От 1 до 20 узлов. `row` и `column` — целые неотрицательные числа; пара уникальна внутри графа. Пропуски номеров не создают пустые ряды/столбцы: значения задают относительный порядок.

`target` имеет ровно одну форму:

- `{"path": "src"}` — описанный каталог или файл;
- `{"section": "algorithm"}` — существующий раздел.

Связь крупного узла с кодом выводится из `target`, без новых обязательных полей: раздел → его `range` или весь файл для списка `scope: "file"`; файл → весь файл; каталог → список явно описанных файлов внутри него. Несколько файлов показываются для выбора, а не подсвечиваются одновременно. Для каталога это выборочная область анализа, а не рекурсивное чтение файловой системы.

Ребро: `{from, to, label}`. Концы — id узлов этого обзора, `label` — непустое объяснение связи. Циклы допустимы; одинаковые тройки `from/to/label` запрещены. Положение узла не означает порядок исполнения.

## Раздел

Общие поля:

| Поле | Значение |
| --- | --- |
| `id`, `title`, `summary` | Идентификатор, название и краткое объяснение |
| `file` | Путь к описанному файлу |
| `scope` | `function`, `fragment` или `file` |
| `range` | Диапазон раздела; обязателен, кроме списка всего файла |
| `layout` | `graph` или `list` |
| `nodes` | Непустой массив узлов |

### Граф алгоритма

`layout: "graph"` требует `scope: "function"` или `"fragment"`, `range`, `entry` (id начального узла) и `edges`. `groups?` — необязательные смысловые группы.

Узел: `{id, kind, title, summary, range, row, column, detail?, callee?}`.

- `kind`: `action`, `condition` или `exit`.
- `title` и `summary` видны в карточке, `detail?` — при выборе. Узел объясняет малую смысловую часть, а не только повторяет код.
- `row/column` следуют правилам обзора; лимит 20 узлов на граф алгоритма не распространяется.
- `condition` обозначает развилку. Для логического условия нужны подписанные выходы «Да»/«Нет», для выбора из вариантов — подписи вариантов и выхода по умолчанию. `&&`/`||` раскладываются в отдельные проверки с соответствующим коротким замыканием.
- `exit` — завершение выбранной области: `return`, покидающий её `throw`, неявный возврат в конце функции либо выход за явно обозначенную границу фрагмента. `throw`, перехватываемый внутри области, остаётся действием с ребром к обработчику, а не выходом без продолжения. Объяснение различает эти случаи. Для неявного возврата якорь можно привязать к закрывающей скобке/последнему участку тела; синтаксис расширение не распознаёт.

Ребро: `{from, to, label?}`, концы внутри раздела. `label` обязателен и непуст у рёбер из `condition`; при наличии у остальных тоже непуст. Обратные переходы и петли разрешены, дубли одной тройки запрещены. `exit` не имеет исходящих рёбер. Каждый невыходной узел имеет исходящий переход, `condition` — не менее двух. Это проверки структуры, а не доказательство соответствия алгоритму.

Полнота всех явных путей, в том числе ошибок, проверяется агентом по исходнику. Несколько последовательных операций можно объединить, но условие или переход внутри такого узла не скрываются. Недостижимый исходный код можно показать отдельными узлами с объяснением недостижимости в `summary`/`detail` узла, не соединяя его ложным исполнимым ребром с остальным графом.

Группа: `{title, nodes, id?, summary?, range?}`. `nodes` — непустой массив id узлов этого раздела; узел входит не более чем в одну группу, вложенности нет.

- Старый вариант `{title, nodes}` остаётся подписью без сворачивания, совместимость сохраняется.
- Для раскрываемого смыслового блока задаются **все три** поля `id`, `summary`, `range`. `id` уникален среди групп и узлов раздела; `summary` объясняет роль блока, включая возможное завершение алгоритма внутри него.
- `range` ищется внутри раздела, как у малого узла. Привязка блока доступна только если диапазон содержит однозначные привязки всех его дочерних узлов. Ошибка не отключает исправные малые узлы.
- Такие блоки первоначально свёрнуты. Карточка показывает число малых узлов, условий и выходов; внутренние рёбра скрыты явно, а не удалены из данных. Внешние рёбра проецируются на блоки с сохранением подписей; одинаковые спроецированные тройки объединяются. Исходные самостоятельные петли сохраняются.
- Пользователь может раскрыть один блок или весь граф. Выбор малого участка кода раскрывает его блок. Числовой масштаб графа (25–200%) независим от этого уровня детализации.

### Независимые операции

`layout: "list"`: `scope: "file"` без `range` либо `scope: "fragment"` с `range`. Узел: `{id, title, summary, range, detail?, callee?}`. Диапазоны узлов списка всего файла ищутся в файле. Порядок в массиве — порядок показа, не исполнения. `entry`, `edges`, `groups`, `kind`, `row` и `column` не задаются. Сложная операция может иметь ссылку на свой раздел через `callee`.

### Вспомогательная функция `callee`

`{file, range, section?}`. `file` — описанный файл; `range` задаёт вызванный код, а не место вызова. `section?` — существующий раздел того же файла для открытия объяснения. Все три поля описывают одну и ту же функцию; смысловое соответствие проверяет агент. Если раздел задан, в его описание можно перейти и вернуться назад; отдельно доступен переход к коду. Если раздела нет, остаётся переход к исходнику. Рекурсивные ссылки допустимы, вложенные графы и собственная Call Hierarchy не строятся.

## Свойства

Элемент `properties`: `{kind, section, node?, subject, text}`.

- `kind`: `precondition`, `postcondition`, `invariant` или `data-contract`.
- `section`: существующий раздел; `node?` — существующий малый узел или `id` раскрываемого блока именно этого раздела.
- `subject`: непустое явное указание области действия, например «вход функции», «голова цикла перед index < values.length», «массив values».
- `text`: содержательное утверждение с основанием в коде или явных требованиях. Пустая или состоящая из пробелов строка скрывается; новые свойства взамен не генерируются. Все остальные поля свойства остаются структурно корректными даже при пустом `text`.

Свойства без `node` относятся к разделу, с `node` показываются также при выборе этого узла. Инвариант цикла не становится инвариантом всей функции, требование к данным не выдаётся за проверку в конструкторе. Источник отображения — утверждение агента; нет полей демостатуса, результата проверки или доказательства.

## Ошибки и обновление

Невалидная структура, версия, ссылка, путь или граф отклоняют новую версию документа целиком с указанием поля/элемента и причины. Отсутствие файла, несовпадение хеша и ошибки якорей — локальные проблемы привязки/актуальности: объяснение остаётся доступным, угадывание переходов запрещено.

Перезагрузка явная. Последний корректный документ сохраняется при ошибке нового, с заметной отметкой о неудачном обновлении. Асинхронный ответ старой загрузки/версии документа не должен заменять новую привязку или подсветку. Расширение не записывает ни JSON, ни исходник.

## Проверяемый пример

Корень целевого проекта для примера — `examples/analysis-contract`, не корень расширения. Документ открывает `algorithm.cjs` относительно этой папки. Вспомогательная `isPositive` имеет отдельный граф без свойств; `sumPositiveUntil` показывает цикл, пропуск, две проверки `||`, ранние выходы и накопление.

Результат — первая накопленная сумма положительных конечных значений, достигшая порога, либо сумма всех подходящих значений при исчерпании массива. Это не ограничение суммы сверху: результат может превысить порог. `limit <= 0` даёт ноль. Вычисления следуют арифметике JavaScript, а не точным вещественным числам.

`test/analysis-example.test.cjs` независимо проверяет поведение исходного примера, ссылки, диапазоны, хеш и согласованные переходы конкретного JSON. `test/analysis.test.cjs` проверяет настоящий валидатор и привязки; `test/analysis-session.test.cjs` — файловую границу и протокол с подменой VS Code API. Пример открывается командой «Анализ агента: Открыть JSON рядом с кодом» в папке `examples/analysis-contract`. Проверки структуры и протокола не доказывают качество анализа, раскладку любого графа или работу в живом VS Code.
