# Как агенту проверять расширение в настоящем VS Code

## Два разных уровня

1. Интеграционные тесты выполняются внутри Extension Development Host и используют настоящий модуль `vscode`. Штатные параметры запуска: `--extensionDevelopmentPath` и `--extensionTestsPath`. Test runner экспортирует `run`; Mocha и скачивание отдельного VS Code не обязательны для самого этого механизма. Официальные обёртки `@vscode/test-cli` и `@vscode/test-electron` упрощают управление запуском, но не заменяют Extension Host. [Testing Extensions](https://code.visualstudio.com/api/working-with-extensions/testing-extension)
2. Проверка внешнего вида и взаимодействия с webview требует управления окном/DOM. Успешный `executeCommand` ещё не доказывает, что webview отрисовалась. Playwright предоставляет экспериментальный `_electron.launch`, `firstWindow`, действия на странице и screenshots, в том числе запуск через `executablePath`. Поддержка Electron экспериментальная; установку библиотеки и способ запуска надо согласовать отдельно. [Playwright Electron](https://playwright.dev/docs/api/class-electron)

## Ограничения запуска

Официальная документация предупреждает: CLI-запуск integration tests той же версии VS Code, которая уже запущена, ограничен. В качестве альтернатив описаны другая версия (Stable/Insiders) и запуск тестов конфигурацией отладчика `type: extensionHost`. Не следует считать `--extensionTestsPath` способом подключить тест к любому уже открытому окну. [Testing Extensions: Tips и Debugging the tests](https://code.visualstudio.com/api/working-with-extensions/testing-extension)

Официальный пример конфигурации тестового F5 использует `--extensionDevelopmentPath` и `--extensionTestsPath`. Его `preLaunchTask` нужен для сборки TypeScript-примера; наш CJS-проект сборки не требует. [Microsoft extension sample: launch.json](https://github.com/microsoft/vscode-extension-samples/blob/main/helloworld-test-sample/.vscode/launch.json)

Для WSL нужно различать локальный UI-host и удалённый workspace-host. У нашего расширения `extensionKind: ["workspace"]`, поэтому проверять нужно код в WSL, а не только Windows-список установленных расширений. [Remote Extensions](https://code.visualstudio.com/api/advanced-topics/remote-extensions)

`extensionMode` доступен на `ExtensionContext`, переданном в `activate`, а не на объекте `Extension`, возвращаемом `extensions.getExtension`. Путь загруженной копии проверяется через `Extension.extensionPath`. [VS Code API](https://code.visualstudio.com/api/references/vscode-api#ExtensionContext)

## Минимальная проверка нашего проекта

- Проверить фактический `extensionPath` против корня текущего проекта, а не против имени/версии расширения: у установленной копии может быть тот же ID и версия.
- Активировать текущую копию, проверить регистрацию `geometry.openDiagram`, открыть реальный geometry-документ и выполнить команду.
- Отдельно подтвердить отображение панели, наличие переключателя прототипа и все три представления.
- Изменить реальный selection редактора и проверить выбор блока в панели; действие в панели проверить по реальному редактору. Повторить для другого файла, несохранённой правки и неоднозначного якоря.
- Проверять фокус и очистку подсветки при закрытии панели. Ошибки Extension Host и renderer проверять по журналам, ограничивая вывод относящимися к сценарию строками.
- Не называть mock-тесты, тест с подменённым webview-мостом или exit code команды `code` проверкой живого редактора.

Отчёт подтвердил путь текущего проекта. Первый тест остановился на ошибочном обращении к `Extension.extensionMode`; это ошибка теста, не доказательство неисправности расширения.
- Доступны штатные Windows UI Automation, управление только явно выбранным тестовым окном и screenshots. Это позволяет продолжить без установки Playwright. Снимки требуют корректного DPI и синхронизации compositor; скриншот не должен захватывать соседние приложения.

## Исправление перекрытия и последующие проверки

С разрешения пользователя в `webview.css` добавлено одно правило: `.prototype .node{scroll-margin-bottom:110px}`. `scrollIntoView({block: 'nearest'})` теперь оставляет место под фиксированную панель. Правило относится только к прототипу; данные схем, C++ и обработчики переходов не менялись.

Проверка реальной раскладки: `node /tmp/algo-scroll-check.cjs` запускает уже установленный Chrome с настоящими HTML/CSS/JS расширения, подменяя только мост VS Code. Проверяет геометрическое условие: нижняя граница выбранного блока с обводкой выше верхней границы панели. До изменения все 9 случаев падали; после — все 9 прошли: три представления при фактической ширине 500, 700 и 1000 px. Запрошенные 360 px Chrome увеличил до 500, поэтому проверку ширины 360 px не заявляем. Фикстуры: `/tmp/algo-scroll-check-ygeGTh` (до) и `/tmp/algo-scroll-check-0JKPi6` (после). Этот временный браузерный check не включён в `npm test` и не является живым VS Code.

В настоящем Development Host дополнительно подтверждены:

- Во всех трёх представлениях выбранный блок виден целиком над панелью. Снимки: `algo-scroll-fixed-{flow,stages,calls}.png`.
- Ссылка «Открыть раздел Vector» открывает реальный `vector.cpp` и меняет представление. Действие на `Length` прокручивает редактор к диапазону 37–45 и подсвечивает его. Курсор при этом не переносится: обработчик намеренно использует `preserveFocus: true` и `revealRange`. Снимки: `algo-live-vector.png`, `algo-live-reveal.png`.
- Несохранённая вставка пустой строки перед `Normalize` сдвигает диапазон 37–45 в 38–46, а демостатусы становятся устаревшими. Undo возвращает чистый буфер и прежние диапазоны. Снимки: `algo-live-unsaved.png`, `algo-live-clean.png`.
- Несохранённый дубликат якоря `const Vector offset` отключает подсветку и блоки, показывает ошибку неоднозначного участка и недоступность актуальных деморезультатов. После Undo буфер чистый, привязки восстановлены. Снимки: `algo-live-ambiguous.png`, `algo-anchor-clean.png`.
- После закрытия панели жёлтая подсветка строк 13–16 исчезает. Снимки: `algo-before-panel-close.png`, `algo-after-panel-close.png`.

Все перечисленные снимки сохранены в `/tmp/algo-vscode-host-proof`. SHA256 файлов `geometry.cpp` и `vector.cpp` на диске до и после совпадают; тестовые правки были только в буферах и отменены. Сессия проверки прокрутки завершилась по пятиминутному тайм-ауту: неуспешный результат сохранён отдельно в `report-scroll-session.json`, он не считается проходом. Последний короткий запуск `2026-11-04T22:06:39.783Z` завершил API smoke успешно (`report.json`), после проверки неоднозначного якоря и закрытия панели. Поиск относящихся к расширению записей в журнале последнего Extension Host показал его активацию, без найденных ошибок по проверенным шаблонам. Это не полный аудит журналов.

Все 16 Node-тестов проходят на итоговом изменённом коде. Полный перебор демостатусов, клавиатурная доступность и окончательная пользовательская оценка читаемости ещё не закрыты. Независимой проверки нет: агент имеет доступ и к коду, и к тестам; снимки предоставляют пользователю отдельное свидетельство, но сами по себе не означают принятие интерфейса.

Этот документ описывает подход и установленные факты, а не итоговую приёмку интерфейса. Результаты конкретных запусков хранятся отдельно; если проверка падает или не выполняется, это не следует скрывать изменением критерия.
